# Plan — M5.1 `m5-command-replay`

**Status:** open. **Branch:** `lane/moba-m5.1-command/<yyyymmdd>` in a `GITHUB-ROOT/_worktrees/`
worktree from green `main`. **Slate to open:** `docs/slate-moba-phase5-m5.1.md`. Can run in parallel
with M5.0 **only** because its fenced files are disjoint; if either lane must touch `sim.h`,
`sim.cpp`, or `sim_hash.cpp`, the second claimant waits for the first to merge.

## Goal

Make the command path a contract instead of a test fixture: the proto-design `Command`,
`CommandReject`, and `SimEvent` shapes; the deterministic per-tick ordering key; rejection of
malformed, wrong-tick, duplicate-sequence, stale-generation, wrong-owner, and over-capacity commands
without mutating authoritative state; and proof that a live command stream and its replay produce
identical hashes, event order, and rejects.

## Spec sources

- `docs/slate-moba-proto-design.md` §3.4 (shapes; ordering key
  `(tick, player_id, sequence, actor.index, command_kind)`; duplicate `(player_id, sequence)` rejected;
  late commands rejected; event buffer full = source operation fails, never drop); §4 rows 1–3
  (ingest, validate/order, apply); §6 row `m5-command-replay`; §7.2 items 1, 2, 3, 9.
- ADR-0014 (command validation, stale targets, event backpressure) and ADR-0013 (no conditional RNG).
- `docs/ROADMAP.md` M5.2 replay-seam note (`SIM_MAX_UNITS = 64` is a format + hash break if widened —
  do not widen here) and M6.0 (per-command reject **reasons** are the M6.0 extension; this lane records
  the reason enum and the reject struct but keeps the existing atomic-reject behavior for the sim).
- Existing seams: `engine/sim/include/sim/replay.h` (replay v1, 16-byte unit-slot commands),
  `sim.h` (`sys_apply_commands`), `events.h` (12-byte `DamageEvent`, phase buffers).

## Write fence

- `engine/sim/include/sim/command.h` (new), `engine/sim/src/command.cpp` (new): `Command`,
  `CommandReject`, reason enum, validate + sort + dedupe over a bounded per-tick batch.
- `engine/sim/src/systems.cpp` — only inside `sys_apply_commands` to call the validator/sorter.
- `tests/sim/command_replay_tests.cpp` (new); `tests/CMakeLists.txt` — `add_test` only.
- `docs/slate-moba-phase5-m5.1.md`, this plan's Status line, ROADMAP M5.2 status note.

## Out of scope

Replay v1 byte format changes (a v2 needs its own ADR); `SimEvent` generic envelope beyond the
existing `DamageEvent` (record the envelope in the slate as designed, implement when hero-combat
needs a second event kind); network intake; presentation input translation (M5.2 Raw Input, G38);
map files (M5.0).

## Slice ledger

- [ ] **S0 Baseline** — same matrix and oracle record as M5.0 S0.
- [ ] **S1 Shapes** — `command.h` with the §3.4 field order; `CommandReject` + reason enum values
  fixed and documented; POD, no padding-dependent bytes.
- [ ] **S2 Validate + order** — bounds, ownership (`player_id` owns `actor`), stale generation,
  wrong tick, duplicate `(player_id, sequence)`, capacity; stable sort by the ordering key; tests
  prove every reject leaves state hash unchanged (§7.2 item 2).
- [ ] **S3 Backpressure** — event buffer full → operation fails, tick not published, nothing dropped
  (§7.2 item 3); test with a deliberately tiny capacity.
- [ ] **S4 Live/replay parity** — record a live stream through `moba_replay`, replay it, compare
  final hash, event order, and the reject list (§7.2 item 1); malformed replay input rejects at the
  first invalid boundary (§7.2 item 9, extending `replay_tests.cpp` patterns).
- [ ] **S5 Gates** — full matrix, isolation lint, oracle unchanged (no logic-hash bump expected; if
  ordering changes the oracle, stop and record), slate, ROADMAP, JOURNAL, PR.
