## The shape of the session

1. **Transactional correctness at scale.** `SimWorldConfig` defaults to 16,384 entities /
   64 replay slots, and invalid or under-budget initialization is atomic — no half-built
   worlds. The "region owns the bytes" doctrine got its first large instance.
2. **Generation strategy was made deliberate:** all 14 ADR-0003 generation bits preserved,
   liveness tracked separately, fresh slots ascending, recycling LIFO, and every failure
   class (exhausted/stale/forged/double-release) rejected *without mutation*.
3. **Deferred destruction became a real pattern:** commits at the tick boundary in request
   order — Health→Velocity→Transform removal, mapping clear, identity release, stale-handle
   safety preserved after reuse.

---

## Cross-cutting decisions

- **Hash authority was defined negatively and positively:** the canonical FNV-1a/64 covers
  config, RNG, lifecycle, free-stack, mapping, queue, membership, and typed values in
  semantic entity-index order — while excluding pointers, padding, unused capacity,
  allocator state, and sparse/dense storage order. Writing down the exclusions is what
  makes the hash *semantic* rather than accidental.
- **Replay stayed format v1 with 16-byte commands** and a deliberate logic-hash move
  (`0x7902599e173f87a6`); M3.0 recordings are intentionally incompatible.
- **`swap-remove` reorders dense** — flagged as the M3.2 risk that the ascending-ordered
  views were built to absorb.

---

## Lessons for future sessions

- **"Reject without mutation" is the only safe failure mode for a deterministic world** —
  a half-applied release is a hash fork waiting to happen.
- **Semantic hashing is a spec, not an implementation detail.** The exclusion list lives in
  the code and tests; a future pool added without hash coverage is the M3.4-era footgun the
  gap-close sweep later guards with a coverage test.
- **Deferred:** M3.2 (queued on its own slate), M3.3/M3.4, cross-binary parity.
